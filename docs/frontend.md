# 03. 프런트엔드 구현 지침

## 1. 기술 범위
- HTML5, CSS3, Vanilla JavaScript만 사용한다.
- SPA 프레임워크, 빌드 도구, CSS 프레임워크를 추가하지 않는다.
- 서버 API와 통신하는 코드는 `assets/js/app.js`에 둔다.
- 디자인 토큰과 반응형 규칙은 `assets/css/styles.css`에 둔다.

## 2. HTML 구조
권장 시맨틱 구조:
- `header`: 브랜드와 내비게이션
- `main`: 히어로, 입력 폼, 결과 영역
- `section`: 분석 결과
- `footer`: 개인정보·AI 결과 한계 안내

입력 폼에는 textarea, 글자 수, 제출 버튼을 포함한다. 결과 컨테이너에는 감성, 신뢰도, 분석 이유를 별도 요소로 둔다.

## 3. 입력 검증
- 앞뒤 공백을 제거한 값이 비어 있으면 제출하지 않는다.
- 최대 5,000자 제한을 적용한다.
- 글자 수는 사용자 입력 기준으로 표시한다.
- 프런트엔드 검증은 편의 기능이며, 서버 검증을 대체하지 않는다.

## 4. API 통신
- `fetch('/api/analyze', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ text }) })` 형태로 요청한다.
- 응답의 HTTP 상태와 JSON 구조를 모두 확인한다.
- 성공 응답에서 감성 레이블, 신뢰도, 이유를 검증한 뒤 화면에 표시한다.
- 네트워크 실패, 서버 오류, 비정상 JSON을 구분해 사용자 메시지를 제공한다.
- 요청 중 버튼을 비활성화하고 `finally`에서 반드시 원상 복구한다.

## 5. 안전한 DOM 렌더링
- 사용자 입력, AI의 `reason`, 오류 메시지는 `textContent`로 넣는다.
- 외부 데이터에 `innerHTML`을 사용하지 않는다.
- 서버에서 전달된 감성 레이블은 허용된 세 값과 일치하는지 확인한다.
- 신뢰도는 유한한 숫자이며 0~100 범위인지 확인한다.

## 6. 결과 표시
- `positive` → `긍정`
- `negative` → `부정`
- `neutral` → `중립`
- 신뢰도는 소수점 없이 백분율로 표시한다.
- 분석 이유는 줄바꿈을 보존할 수 있으나 HTML로 해석하지 않는다.
- `AI 신뢰도(참고용)` 문구와 한계 안내를 함께 표시한다.

## 7. 완료 기준
- 입력, 글자 수, 검증, 로딩, 성공, 오류 상태가 모두 구현되어 있다.
- 연속 클릭으로 중복 요청이 발생하지 않는다.
- API 실패 후 입력 내용이 유지되고 다시 요청할 수 있다.
- 키보드로 입력 및 제출이 가능하다.
- 모바일 화면에서 입력창과 결과 카드가 깨지지 않는다.
